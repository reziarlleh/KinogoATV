## Закрытый шлюз

В `.env` APK указан базовый адрес:

```text
https://api.kinogo-10.biz/gateway
```

Запросы требуют заголовок `X-App-Signature`. В официальном APK его значение совпадает с
SHA-256 сертификата, которым подписан APK; это воспроизводимо через `apksigner --print-certs`.
Без заголовка шлюз возвращает HTTP 403. Это регистрационный барьер приложения, а не
пользовательский секрет, но контракт не документирован и может быть изменён или отозван.
Поэтому наш клиент не должен зависеть от шлюза при запуске и не должен молча выдавать себя
за официальное приложение.

Авторизованные запросы дополнительно используют:

```text
Authorization: Bearer <access_token>
```

Модель токенов: `access_token`, `refresh_token`, `expires_in`. В официальном приложении
токены хранятся в Flutter Secure Storage; логин и пароль не сохраняются. В нашем TV-клиенте
сохранение логина и пароля остаётся намеренно включённым для автоматического повторного входа.

## Подтверждённые маршруты

- `GET /v1/post?page=&per_page=&sort=&order=` — каталог и пагинация;
- `GET /v1/filters` — серверные сортировки, фильтры, xfields и их значения;
- `GET /v1/post/{id}` — полная карточка;
- `GET /v1/post/custom?ids=...` — пакетное получение карточек по ID;
- `GET /v1/post/by-category/{id}` — категория;
- `GET /v1/post/xfsearch?field=...&value=...` — фильтр по xfield;
- `GET /v1/post/lightsearch?q=...` — быстрый поиск, минимум три символа;
- `GET /v1/podborki` — подборки;
- `GET /v1/post/{id}/comments` и `GET /v1/post/{id}/rating`;
- `GET /v1/post/{id}/player` — описание доступных iframe-плееров;
- `POST /auth/login`, `/auth/register`, `/auth/refresh`, `/auth/logout`;
- `GET/PUT /v1/users/profile`, `POST /v1/users/avatar`;
- `/v1/favorites`, `/v1/favorites/ids`, `/v1/favorites/{postId}`.

Каталожная модель содержит, среди прочего, `poster`, `kinopoisk_id`, тип, оригинальное
название, год, страну, жанры, актёров, режиссёра, качество и перевод. Это позволяет в будущем
уменьшить зависимость каталога от изменчивой HTML-вёрстки.

## Плеер и история

Ответ player-маршрута имеет форму `post_id`, `has_player`, `trailer`, `tabs[]`, `mirrors[]`.
Вкладка содержит `id`, `title`, `balancer`, `iframe_url`, `is_serial`; зеркало — `provider` и
`iframe_url`. На момент проверки встречались Cinemar и Alloha.

Прямые HLS/DASH/MP4 URL, нативная матрица сезонов, серий, озвучек и качества через этот
маршрут не выдаются. Официальное приложение открывает выбранный iframe в полноэкранном
WebView. Этот подход не переносим в наш TV-first плеер: он хуже управляется пультом и не даёт
надёжного нативного resume.

История официального приложения — два локальных списка ID (`viewed_post_ids` и
`player_viewed_post_ids`), которые разрешаются через batch lookup. В коде приложения нет
модели точной позиции, сезона, серии, озвучки или серверной синхронизации progress. Состояние
может отдельно сохраняться внутри cookies/localStorage iframe-провайдера, но это не аккаунтная
модель самого приложения.

Официальный APK поддерживает только независимое «Избранное». Статусов сайта «Смотрю»,
«Смотрел», «Буду», «Бросил» в нём не обнаружено. Наша HTML-синхронизация этих статусов должна
быть сохранена.

## Как использовать знания в TV-клиенте

Безопасная архитектура следующего этапа:

1. Добавить `OfficialGatewayCatalogSource` за существующим интерфейсом каталога.
2. Использовать его для каталога, фильтров, поиска, карточек и discovery iframe-провайдера.
3. Оставить HTML-парсер полноценным fallback и единственным источником статусных закладок.
4. Не блокировать запуск проверкой версии, Firebase или доступностью закрытого шлюза.
5. Не переносить WebView-плеер; для каждого провайдера нужен отдельный документированный
   нативный адаптер, который возвращает явные HTTPS media URL и проходит текущие SSRF/TLS-
   проверки.
6. Считать контракт нестабильным: покрыть JSON fixtures контрактными тестами и включать
   источник feature-флагом, чтобы его можно было отключить без выпуска аварийной версии.
